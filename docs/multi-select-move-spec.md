# 멀티 선택 이동 동작 명세 (바탕화면/폴더 매니저 공통)

본 문서는 바탕화면(루트 App) 및 폴더 매니저 내부에서 멀티 선택된 노드를 드래그하여 이동할 때의 기대 동작을 정의합니다. 구현은 `src/utils/rectangleDrag.js`, `src/utils/tempDragger.js`, `src/utils/dropHandlerApp.js`를 중심으로 이루어집니다.

## 용어
- 선택 집합: 동시에 이동되는 노드들의 집합. 각 노드는 그리드 좌표 `(col, row)`를 가짐.
- 기준(앵커) 노드: 사용자가 실제로 "잡고" 드래그를 시작한 노드. `window.dragStartNode`로 식별.
- 타겟 래퍼(node-wrapper): 그리드의 한 칸을 나타내는 컨테이너.

## 그리드/좌표
- 바탕화면과 폴더 매니저는 CSS Grid 기반의 래퍼 셀로 배치됩니다.
- 각 노드는 드롭 시 해당 좌표의 래퍼로 이동합니다.

## 기본 규칙
1) 기준 노드 앵커링
- 드래그의 기준은 항상 사용자가 처음 집은 기준(앵커) 노드입니다.
- 멀티 선택된 나머지 노드는 기준 노드와의 상대 오프셋을 유지합니다.

2) 상대 오프셋 보존(가로/세로 모두)
- 드래그 시작 직전의 스냅샷 좌표를 사용합니다.
- 모든 선택 노드 i에 대해:
  - `offsetX_i = col_i - col_anchor`
  - `offsetY_i = row_i - row_anchor`
- 드롭 시 기준 노드가 타겟 `(tcol, trow)`에 들어가면, 노드 i는 `(tcol + offsetX_i, trow + offsetY_i)`로 이동을 시도합니다.

3) 선택 노드 간 충돌 무시
- 이동 중 선택 집합 내부의 충돌은 무시합니다. 즉, 선택 노드는 서로를 막지 않습니다.
- 타겟 래퍼가 현재 선택 노드로만 차있다면, 해당 래퍼는 “비어있는 것”처럼 취급되어 정상 배치가 가능합니다.

4) 폴더 우선 드롭
- 드롭 대상이 폴더일 경우: 해당 폴더 내부로 이동(= 북마크 트리에서 부모 변경)합니다.
- 폴더가 아닌 빈 래퍼가 타겟이면: 해당 그리드 위치에 배치합니다.

## 충돌 처리(선택 외 노드와의 충돌)
- 타겟 래퍼가 선택 외 노드로 점유된 경우에는 해당 래퍼를 점유 해제하지 않습니다.
- 현재 구현은 다음의 원칙을 따릅니다:
  - 선택 노드를 우선 정해진 타겟 좌표에 시도합니다.
  - 선택 외 노드가 차지한 래퍼에는 밀어내기 또는 강제 교환을 수행하지 않습니다.
  - 구현 세부: 가용 래퍼 탐색(최근접/행우선)은 최소화되어 있으며, 패턴 보존을 우선으로 하되, 불가 시 해당 개별 노드만 배치 실패로 남을 수 있습니다. (추가 개선 여지)

## 경계/불가 상황
- 그리드 바깥으로 나가는 좌표는 배치하지 않습니다. 해당 노드는 원위치로 복구됩니다.
- 드래그 중 해제(ESC 등) 시 전체 이동이 취소됩니다.

## 폴더 드롭 상세
- 폴더 위에 드롭하면 선택된 모든 노드는 해당 폴더로 이동합니다.
- 폴더 내부 배치는 폴더의 정렬/레이아웃 설정에 따릅니다.
- 드롭 성공 시 멀티 드래그 상태는 즉시 해제됩니다.

## 시각/상태
- 멀티 드래그 보조 애니메이션/오버레이는 사용하지 않습니다.
- 드롭 성공 시 즉시 글로벌 상태를 정리합니다.

## 예시
1) 2x2 블록 이동(오프셋 보존)
- 초기 선택: (2,3),(3,3),(2,4),(3,4)
- 사용자가 (3,3)을 집어 (5,3)으로 드래그/드롭
- 오프셋: (−1,0),(0,0),(−1,1),(0,1)
- 결과: (4,3),(5,3),(4,4),(5,4)

2) 1x2 세로 블록 이동
- 초기 선택: (1,1),(1,2); 사용자가 (1,2)를 집어 (4,2)로 드롭
- 오프셋: (0,−1),(0,0)
- 결과: (4,1),(4,2)

3) 충돌 무시(선택 내부)
- 타겟 (5,3)에 기존에 선택 중인 노드가 있어도, 해당 래퍼는 비어있는 것으로 간주되어 정상 배치.

4) 충돌 발생(선택 외 노드)
- 타겟 (6,3)이 선택 외 노드로 이미 점유됨
- 해당 좌표에는 배치하지 않으며, 인접 가용 래퍼 탐색은 제한적입니다(현 구현). 불가 시 해당 노드만 배치 실패로 남을 수 있음.

## 수학적 정의
- 드래그 시작 스냅샷에서
  - 앵커: `(ax, ay)`
  - 각 노드 i: `(xi, yi)`
  - 오프셋: `(dx_i, dy_i) = (xi - ax, yi - ay)`
- 드롭 타겟에서 앵커 타겟 `(tx, ty)`이면 노드 i 타겟 `(tx + dx_i, ty + dy_i)`
- 배치 규칙:
  - 선택 내부 래퍼 점유는 무시
  - 선택 외 점유는 유지(강제 이동/교체 없음)

## 수용 기준(간단 테스트)
- 기준 노드를 바꾸어 드래그해도 결과 패턴이 동일해야 한다.
- X/Y 축 모두에서 오프셋이 정확히 유지되어야 한다.
- 선택 내부 충돌은 드롭 성공의 장애가 되지 않아야 한다.
- 폴더 드롭 시 모두 폴더로 이동해야 하며, 드롭 성공 후 상태가 정상적으로 초기화되어야 한다.

## 향후 개선(제안)
- 비어있는 래퍼 탐색 휴리스틱(최근접, 행우선/열우선 선택)을 도입해 패턴 유지율 개선.
- 큰 선택 집합의 경계 검증/자동 스크롤 보조.
- 디버그 로깅 토글과 간단한 단위 테스트 추가.
